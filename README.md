# Code Review

1. Використання нетипових префіксів `take*` / `put*` замість стандартних `get*` / `set*`.
2. Метод перевірки рівносторонності названий `equilateral()`, хоча для булевих методів краще додавати `is` на початок `isEquilateral()`.
3. Назви методів обчислень `perim()` та `area()` варто змінити на `perimeter()` / `getArea()`.
4. Відсутня перевірка вхідних даних - можна передати нулі або мінусові числа.
5. Відсутність перевірки нерівності трикутника (сума двох менших сторін має бути більшою за третю).
6. Конструктор за замовчуванням створює невалідний трикутник зі сторонами `0.0`.
7. Поля `a`, `b`, `c` можна зробити незмінними (`final`).
8. Повторне обчислення півпериметра всередині методу `area()` замість збереження в локальну змінну.
9. Надмірний блок `if-else` у методі `equilateral()` замість повернення результату умови.
10. Пряме порівняння чисел типу `double` через `==` без урахування похибки.
